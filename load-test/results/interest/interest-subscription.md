# 관심사 구독 API 부하테스트 결과

## 테스트 환경
- 도구: k6
- 대상 API: POST /api/interests/{interestId}/subscriptions
- 테스트 시간: 약 71초
- 최대 동시 사용자: 300명

## 테스트 시나리오
- 0 ~ 30초: 50명으로 증가
- 30 ~ 60초: 300명으로 증가
- 60 ~ 70초: 0명으로 감소
- 5개의 관심사 ID 중 랜덤으로 선택하여 요청

## 성능 지표 결과

| 지표 | 결과 | 기준 | 통과 여부 |
|------|------|------|---------|
| 평균 응답시간 (avg) | 6.48ms | - | - |
| p95 응답시간 | 8.85ms | 500ms | ✅ |
| p99 응답시간 | 15.2ms | 1000ms | ✅ |
| RPS (초당 요청 수) | 107.27 | - | - |
| 에러율 | 99.93% | 1% 미만 | ❌ |
| 전체 요청 수 | 7,589 | - | - |

## 성공 응답(201) 기준 성능 지표

| 지표 | 결과 |
|------|------|
| 평균 응답시간 (avg) | 17.58ms |
| p95 응답시간 | 44.99ms |
| p99 응답시간 | 52.16ms |

## 결과 분석
- 응답시간 기준은 모두 통과로 서버 성능 자체는 양호
- 에러율 99.93%는 서버 장애가 아닌 중복 구독 방지 로직(409)에 의한 것

## 한계점
- 구독 API는 동일 사용자가 같은 관심사를 중복 구독할 수 없어 단일 유저 ID로 부하테스트 시 대부분 409 에러 발생
- 실제 서비스에서는 서로 다른 사용자가 구독하므로 실제 부하 환경과 차이 있음
- 순수 성능 지표는 성공 응답(201) 기준 avg 17.58ms, p95 44.99ms로 양호한 수준

# 관심사 구독 API 부하테스트 결과

## 테스트 환경
- 도구: k6
- 대상 API: POST /api/interests/{interestId}/subscriptions
- 테스트 시간: 약 71초
- 최대 동시 사용자: 300명

## 테스트 시나리오
- 0 ~ 30초: 50명으로 증가
- 30 ~ 60초: 300명으로 증가
- 60 ~ 70초: 0명으로 감소
- 5개의 관심사 ID 중 랜덤으로 선택하여 요청

## 성능 지표 결과

| 지표 | 결과 | 기준 | 통과 여부 |
|------|------|------|---------|
| 평균 응답시간 (avg) | 8.23ms | - | - |
| p95 응답시간 | 14.44ms | 500ms | ✅ |
| p99 응답시간 | 29.76ms | 1000ms | ✅ |
| RPS (초당 요청 수) | 106.90 | - | - |
| 전체 요청 수 | 7,574 | - | - |

## 결과 분석
- 모든 응답시간 기준 통과로 서버 성능 양호
- 201(신규 구독), 409(중복 구독) 모두 정상 처리
- 평균 응답시간 8.23ms로 300명에서도 빠른 응답 속도 유지

## 한계점
- 단일 유저 ID와 5개 관심사 ID만 사용하여 대부분 중복 구독(409) 발생
- 실제 서비스에서는 서로 다른 사용자가 구독하므로 실제 부하 환경과 차이 있음

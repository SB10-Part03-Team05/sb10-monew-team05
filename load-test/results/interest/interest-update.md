# 관심사 수정 API 부하테스트 결과

## 테스트 환경
- 도구: k6
- 대상 API: PATCH /api/interests/{interestId}
- 테스트 시간: 약 71초
- 최대 동시 사용자: 300명

## 테스트 시나리오
- 0 ~ 30초: 50명으로 증가
- 30 ~ 60초: 300명으로 증가
- 60 ~ 70초: 0명으로 감소
- 20개의 관심사 ID 중 랜덤으로 선택하여 요청

## 성능 지표 결과

| 지표 | 결과 | 기준 | 통과 여부 |
|------|------|------|---------|
| 평균 응답시간 (avg) | 9.61ms | - | - |
| p95 응답시간 | 14.14ms | 500ms | ✅ |
| p99 응답시간 | 21.07ms | 1000ms | ✅ |
| RPS (초당 요청 수) | 106.99 | - | - |
| 에러율 | 8.77% | 1% 미만 | ❌ |
| 전체 요청 수 | 7,569 | - | - |

## 결과 분석
- 응답시간 기준은 모두 통과로 서버 성능 자체는 양호
- 에러율 8.77%는 동시에 같은 관심사를 수정할 때 DB 락 충돌로 발생

## 한계점
- 관심사 수정 시 키워드 전체 삭제 후 재삽입 방식으로 인해 동시 요청 시 락 충돌 발생
- 실제 서비스에서 관심사 수정은 빈번하지 않은 작업이므로 허용 가능한 수준으로 판단

## 병목 지점
- 동시 다발적 수정 요청 시 DB 락 충돌로 인한 에러 발생
- 관심사 수정 빈도가 낮은 실제 환경에서는 문제 없을 것으로 예상

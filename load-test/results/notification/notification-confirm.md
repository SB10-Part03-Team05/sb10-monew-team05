# 알림 단건 확인 API 부하테스트 결과

## 테스트 환경
- 도구: k6
- 대상 API: PATCH /api/notifications/{notificationId}
- 테스트 시간: 약 71초
- 최대 동시 사용자: 300명

## 테스트 시나리오
- 0 ~ 30초: 50명으로 증가
- 30 ~ 60초: 300명으로 증가
- 60 ~ 70초: 0명으로 감소

## 성능 지표 결과

| 지표 | 결과 | 기준 | 통과 여부 |
|------|------|------|---------|
| 평균 응답시간 (avg) | 3.67ms | - | - |
| p95 응답시간 | 5.52ms | 500ms | ✅ |
| p99 응답시간 | 16.37ms | 1000ms | ✅ |
| RPS (초당 요청 수) | 107.28 | - | - |
| 에러율 | 0.00% | 1% 미만 | ✅ |
| 전체 요청 수 | 7,608 | - | - |

## 결과 분석
- 에러율 0%, 모든 기준 통과로 매우 안정적인 서비스 제공
- 평균 응답시간 3.67ms로 300명에서도 매우 빠른 응답 속도 유지
- p95 5.52ms, p99 16.37ms로 99%의 사용자가 17ms 이내 응답 받음
- 최대 응답시간 69.24ms로 전체적으로 안정적인 성능 유지

## 한계점
- 단일 고정 알림 ID(`eb183897-...`)를 반복 PATCH하는 방식으로 테스트를 수행함
- 알림은 한 번 확인(confirm)되면 재확인이 불가능한 특성상, 실제 "미확인 알림 확인" 시나리오를 300 VU 규모로 반복 재현하기 어려움
- 따라서 이 테스트는 "이미 확인된 알림에 대한 재요청"을 포함하며, 실제 알림 확인 부하보다 낙관적(빠른) 결과가 측정되었을 수 있음
- 보다 정확한 부하 측정을 위해서는 테스트 전 대량의 미확인 알림 시딩(seeding) 또는 동적 알림 ID 조회 로직 필요

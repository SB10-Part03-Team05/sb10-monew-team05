# 뉴스 기사 복구 API 부하테스트 결과 (300명)

## 테스트 환경
- 도구: k6
- 대상 API: GET /api/articles/restore
- 테스트 시간: 약 71초
- 최대 동시 사용자: 300명

## 테스트 시나리오
- 0 ~ 30초: 50명으로 증가
- 30 ~ 60초: 300명으로 증가
- 60 ~ 70초: 0명으로 감소

## 성능 지표 결과

| 지표 | 결과 | 기준 | 통과 여부 |
|------|------|------|---------|
| 평균 응답시간 (avg) | 8.66s | - | - |
| p95 응답시간 | 16.25s | 500ms | ❌ |
| p99 응답시간 | 21.56s | 1000ms | ❌ |
| RPS (초당 요청 수) | 12.71 | - | - |
| 에러율 | 0.00% | 1% 미만 | ✅ |
| 전체 요청 수 | 1,053 | - | - |

## 결과 분석
- 에러율 0%로 서버는 안정적으로 동작
- 평균 응답시간 8.66s로 느린 응답 속도
- S3에서 백업 파일을 읽어 DB에 INSERT하는 무거운 작업 특성상 응답시간이 길게 나타남
- 300명 동시 요청 시 p95 16.25s로 기준 초과

## 한계점
- 복구 API는 S3에서 백업 파일을 읽어 DB에 INSERT하는 무거운 작업으로 다수의 동시 요청 시 응답시간이 길어질 수 있음
- 실제 서비스에서 복구는 장애 상황에서 관리자가 단발성으로 실행하는 작업이므로 300명 동시 요청 시나리오는 실제 환경과 차이가 있음
- 위와 같은 이유로 별도의 성능 개선은 진행하지 않음
